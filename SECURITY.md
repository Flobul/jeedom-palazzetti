# Politique de sécurité

## Versions prises en charge

Seule la dernière version publiée du plugin bénéficie des correctifs de sécurité. Avant de signaler un problème, vérifiez qu’il est toujours reproductible avec cette version et avec une version de Jeedom encore maintenue.

## Signaler une vulnérabilité

Ne publiez pas de vulnérabilité dans une issue publique. Utilisez en priorité les [GitHub Security Advisories](https://github.com/Flobul/jeedom-palazzetti/security/advisories/new) lorsqu’ils sont disponibles. À défaut, contactez le mainteneur de manière privée depuis son profil GitHub.

Le signalement doit préciser :

- la version du plugin et de Jeedom ;
- les étapes de reproduction ;
- l’impact estimé ;
- les journaux utiles après suppression des données sensibles ;
- une proposition de correction ou d’atténuation, si vous en disposez.

Ne transmettez jamais de mot de passe, jeton, clé API, certificat privé, cookie de session ou sauvegarde Jeedom complète. Un accusé de réception sera envoyé dès que possible, puis la correction sera préparée avant toute divulgation publique.

## Bonnes pratiques

- Maintenez le plugin et Jeedom à jour.
- Limitez les permissions des comptes, jetons et clés au strict nécessaire.
- Stockez les identifiants dans les mécanismes sécurisés prévus par Jeedom et GitHub.
- Vérifiez et expurgez les journaux avant de les partager.
