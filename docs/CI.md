# Repository-local CI

These files are development tooling only and are not loaded by Jeedom at runtime.

The six workflows coordinate PHP syntax and PHPStan, frontend syntax/ESLint/CSS diagnostics, Jeedom structure, security/dependency audits, and i18n generation. Certain syntax, malformed metadata, high-confidence secrets, and exploitable dependency findings are blocking. PHPStan, style harmonization, jQuery migration and Jeedom convention findings begin as explicit warnings, without broad exclusions or `continue-on-error`.

Static CI does not verify rendered tile widths, visual layout, or runtime `Modification en cours…` behavior; those require browser tests.

Translation uses pinned Jeedom core and `jeedom/jeetranslate`, preserves existing manual values, validates placeholders, and opens a reviewable PR limited to `core/i18n/*.json` and `plugin_info/info.json`. Required repository secret: `DEEPL_API_KEY`. Fork pull requests only validate current translations and do not receive secrets or write permissions.

`market_badges.py` regenerates the Jeedom market badge block (rating, price, discount, purchases, downloads, comments) in `README.md`, between the `market-badges:start` and `market-badges:end` markers. The `Market badges` workflow runs after a push to the default branch, every Monday at 04:17 UTC and on demand. It commits only when a value actually changed. The generated commit contains `[skip ci]`, so a changing download counter does not start the full repository CI again.

Published plugins pin `"market": {"id": <n>}` in `ci-config.json`, avoiding fragile HTML catalogue discovery during normal refreshes. The returned market `logicalId` is still checked against the plugin's `plugin_info/info.json` id on every run, so a stale or incorrect pin cannot publish another plugin's figures. Plugins not published yet retain automatic catalogue discovery; every candidate is accepted only after the same `logicalId` check (`LG ThinQ Local` can therefore never inherit `LG ThinQ` badges).

The workflow writes only for trusted scheduled/manual events and pushes to the default branch; pushes to feature branches are ignored. GitHub Actions use explicit major versions (`actions/checkout@v7`, `actions/setup-python@v7`). The workflow runs `test_market_badges.py` before modifying the README and rebases before pushing. Invalid configuration, malformed markers, ambiguous lookup or a market outage prints a notice or warning and leaves `README.md` untouched: a badge refresh must never corrupt the README or turn the repository red because the external market is unavailable.

`readme_badges.py` repairs the repository badges of a **private** repo. shields.io queries the GitHub API unauthenticated, so every `img.shields.io/github/*` badge renders "repo not found" on a private repository — a `dynamic/json` badge pointing at `api.github.com` fails identically. The `GITHUB_TOKEN` provided to the `README badges` workflow *can* read the repo, so the script resolves license, top language, last commit, open issues and open pull requests once and rewrites those five routes as static shields.io badges. No GitHub API call happens when the README is displayed, so the badges render for anyone, private repo or not.

`github/issues` is a prefix of `github/issues-pr`, so the routes are rewritten longest-first with a trailing guard; without it the pull-request badge is silently replaced by the issues badge. Open counts come from the `rel="last"` page number of a `per_page=1` request, so one request yields the total. The workflow follows the same conventions as the market badges job: pinned action majors, a unit test run before the write, `[skip ci]` on the commit, rebase before push, and `exit 0` with a warning on any API problem.

`report_ci.py` runs in the `report` job of `ci.yml`, after every other job and with `always()`, on the default branch only. It reads the jobs of the current run plus the check-run annotations of the commit, writes the summary to `GITHUB_STEP_SUMMARY`, and creates or updates a single rolling issue titled `[CI] Rapport qualité automatique` instead of leaving one issue per failure. When the run is clean it comments and closes that issue. `pull_request` runs are excluded because fork branches are untrusted and their annotations are not actionable in the default branch's issue. Missing environment variables exit `2`; an API error prints a warning and exits `0`, so a reporting failure never masks a green CI.

`check-php.yml`, `ci-config.json`, `phpstan.neon` and `translation.yml` carry per-plugin values and are the only files expected to differ between repositories: the PHP matrix, the branch list, the `3rdparty/Capabilities.php` scan entry, and the declared i18n language list. Every other CI file is byte-identical across the fleet, so a fix made in one repository can be copied to the others without adaptation.
